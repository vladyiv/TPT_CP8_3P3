#### Для чего предназначены модульные тесты?
Модульные тесты нужны для проверки отдельных частей (модулей) программы. Они облегчают поиск багов, экономят время на проверку работы системы и сценариев.

#### Чем отличается NUnit от xUnit?

| NUnit | xUnit |
| :--- | :--- |
| Появился раньше, после создания фреймворка JUnit | Появился позже, с участием разработчика NUnit |
| Имеет отдельные атрибуты `SetUp` и `TearDown` | Не имеет отдельных атрибутов (использует конструктор и `IDisposable`) |
| Классический подход к написанию тестов | Упрощение архитектуры тестов |
| Широко использовался во времена .NET Framework | Хорошая интеграция с современным .NET, считается стандартом |

\+ немного отличается синтаксис (например, фикстуры и assert).

#### Что такое параметризация тестов?
Параметризация — это настройка входных тестовых данных и зависящих от них ожидаемых результатов (мы использовали её в КТ3, когда писали тест для функции is_even(number) с проверкой на разные числа, неверные типы данных и т.д).

#### Для чего используются фикстуры?
Фикстуры используются в написании тестов для настроек перед (SetUp) и после (TearDown) выполнения теста и для обозначения самих тестов (Fact/Test).

#### Зачем тестировать работу репозиториев?
Тесты репозиториев используются для проверки взаимодействия кода с базой данных или работы api-приложения с пользователями (как в нашем случае). Только тестирование поможет обнаружить баги и проверить, корректно ли работает та или иная часть приложения;

#### Как выполняется запуск тестов в .NET? (укажите в какой IDE работаете)
В Visual Studio можно запустить тесты в терминале командой dotnet test или в правой панели в разделе "Обозреватель тестов" (можно запустить сразу все или отдельный тест/раздел).

#### Что общего между pytest и xUnit?
- Компактность кода: в pysettest нет необходимости создавать отдельные классы, в xUnit нет фикстур типа SetUp и TearDown;
- Тесты по умолчанию независимы;
- Предоставляют возможность параметризировать тесты;
- Используется краткий assert или Assert.{Equal, к примеру}(item1, item2), в то время как в NUnit Assert более громоздкий;

#### В чем преимущества pytest?
- Простота синтаксиса (как и у Python в целом);
- Развитая система фикстур и простая параметризации;
- Огромное количество готовых расширений;
- Краткость кода; нет необходимости писать целые классы для тестирования;

#### Для каких задач может быть интересен Expecto?
Expecto — это тестовый фреймворк для работы с F#, имеющий структуру функционального программирования.
Благодаря этой структуре Expecto применяется для разных видов тестирования:
- Модульное тестирование (удобно тестировать каждую функцию отдельно);
- Регрессионное тестирование;
- Тестирование скорости и производительности;
- Параметризованные тесты (удобно писать их без атрибутов в отличие от NUnit, например);
